# Спецификация: Минимальная email-based OTP

## Функциональные требования

**REQ-OTP-001**: Система отправляет OTP коды на email при входе
- При каждой попытке входа с email/password
- 6-значный числовой код
- Действителен 5 минут
- Хранится только в памяти сервера

**REQ-OTP-002**: Пользователи могут войти с OTP
- После получения кода на email
- Ввод username, email и OTP для завершения аутентификации
- Возврат JWT токена при успехе

**REQ-OTP-003**: Система поддерживает повторную отправку
- Новый код заменяет предыдущий
- Rate limiting предотвращает abuse

## Нефункциональные требования

### Безопасность
- OTP коды хранятся только в памяти сервера
- Email адреса хэшируются для ключей кэша
- Rate limiting предотвращает abuse
- HTTPS обязателен для всех операций

### Производительность
- In-memory cache для быстрого доступа
- Email отправка не блокирует основной поток
- Минимальный overhead на обычную аутентификацию

## Критерии приемки

- [ ] Пользователь вводит username, email и password
- [ ] При входе отправляется OTP на указанный email
- [ ] Введенный OTP код дает доступ к системе
- [ ] Неправильный код показывает ошибку
- [ ] Можно отправить новый код
- [ ] Rate limiting работает

## Тестовые сценарии

### Основной поток
1. Ввод username/email/password → отправка OTP
2. Ввод username/email/OTP → успешный вход

### Edge cases
1. Неправильный OTP → ошибка
2. Повторная отправка → новый код
3. Неверный username → ошибка
