# Change: Add Email-Based Two-Factor Authentication

## Why

В настоящее время система использует только парольную аутентификацию, что делает аккаунты уязвимыми к компрометации. Добавление двухфакторной аутентификации (2FA) на базе email повысит безопасность, особенно для пользователей с ролями admin и nikita. Email-based 2FA проще в реализации и использовании по сравнению с TOTP приложениями.

## What Changes

- Добавление поддержки email-based OTP (One-Time Password) для 2FA
- **Архитектура без хранения состояния**: Email вводится пользователем при каждом логине, нигде не сохраняется
- Модификация процесса логина для поддержки email OTP верификации
- Добавление email сервиса с использованием nodemailer и Mailpit для разработки
- Добавление API endpoints для верификации OTP
- Обновление UI для ввода email и OTP кода при логине
- **BREAKING**: Изменение процесса аутентификации - пользователи должны будут предоставлять email и OTP код при каждом входе

## Impact

- Affected specs: auth (новая спецификация аутентификации)
- Affected code:
  - `backend/src/routes/auth.ts` - модификация логина и новый endpoint для верификации OTP
  - `backend/src/utils/` - новые утилиты для генерации OTP и отправки email
  - `backend/src/services/` - email сервис с nodemailer
  - `frontend/src/api/auth.api.ts` - модификация login API для поддержки email + OTP
  - `frontend/src/pages/Login.tsx` - обновление формы логина для ввода email и OTP
- New dependencies: nodemailer, mailpit для локальной разработки
- No database schema changes required

## Architecture Decisions

### Stateless 2FA Architecture

Email адреса для 2FA **вообще не хранятся** - ни в базе данных, ни в сессии. Пользователь вводит email при каждом логине вместе с username/password. Это обеспечивает:

- **Максимальная простота** - нет необходимости в хранении состояния 2FA
- **Отсутствие миграций БД** - не нужно менять схему таблицы users
- **Отсутствие зависимостей** - не нужен Redis или session store для 2FA
- **Приватность** - email не сохраняется нигде в системе
- **Минимальный код** - меньше логики для управления состоянием

### 2FA Flow

2FA работает всегда для всех пользователей:

- **Логин**: username + password + email → OTP отправляется на email
- **Верификация**: ввод OTP кода в течение 1 минуты (макс 3 попытки)
- **Хранение**: OTP коды хранятся в памяти сервера с автоматической очисткой
- **Нет настройки/отключения** - 2FA всегда активно

### OTP Implementation Details

- **Expiration**: 1 минута с момента генерации
- **Storage**: In-Memory Map (теряется при перезапуске сервера)
- **Rate Limiting**: Максимум 3 попытки ввода на один OTP
- **Cleanup**: Автоматическая очистка истекших кодов каждые 5 минут

Это самая простая возможная реализация 2FA.
